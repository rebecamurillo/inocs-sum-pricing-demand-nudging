# Notes on the model — what the package needs and where it resists

Facts about `sum_nsm_dynamic_pricing` 0.1.0 that the demonstrator must work around in its
adapter, since the package is not modified. Each entry cites the file. Add to this list
when a new one is found; report each to the model's author.

| # | Fact | Where | Effect on the demonstrator |
| --- | --- | --- | --- |
| 1 | The solver sets `NodefileDir` to a Windows path (`C:\b_b_gurobi`) | `optimizer/solver.py` (~line 616) | On macOS and Linux a folder of that name may be created in the working directory of a run |
| 2 | The summary hard-codes a bike cost of 0.5 and a per-minute logic | `optimizer/metrics.py` | Profit and cost per ride cannot be read from the package's summary |
| 3 | `display()` is called outside IPython, but not reached: `optimizer.summarize` passes `show=False`, and the call only runs when `show` is true | `optimizer/metrics.py:157-158`, `optimizer/__init__.py:80-81` | None; never call `summarize_experiment_solutions` with `show=True` |
| 4 | Every stage reads and writes files under one `output_dir` | `pipeline.py`, `config.py` | A run needs its own directory |
| 5 | A run needs a Gurobi licence, an OpenTripPlanner server and, unless a local file is given, the Donkey Republic feed | `optimizer/solver.py`, `routing/otp_client.py`, `stations/providers/donkey.py` | The API must start and serve stored results without them |
| 6 | The routing moment is one fixed timestamp, by default Sunday 2026-03-08, which lies outside the validity of the committed GTFS feed (2024-12-15 to 2025-12-13, `feed_info.txt`); `otp_client.py` formats the digits of the timestamp and OpenTripPlanner reads them in the feed's time zone | `config.py:25` (`otp_timestamp`), `routing/otp_client.py:96-101` | A run with the default date finds no public transport; each period stores its routing date and time, the worker writes `otp_timestamp` from them (the local wall clock with a `Z` suffix), and a rule refuses a date outside the feed |
| 7 | The only GTFS file in the repository is under a legacy folder | `Geneva_Complete_Link_Instances_and_Optimization/OTP2_Geneva_Instances/tpg_gtfs.zip` | It may be read as input data; nothing else in that folder is used |
| 8 | `gurobipy` installed from PyPI starts under a built-in size-limited licence: an environment starts, and a model over the limit fails at `optimize()` with error 10010 | observed with `gurobipy` 14.0.0 (2026-11-25) | "A Gurobi environment starts" does not mean a city-sized run can be solved; the solver's status must tell the two apart |
| 9 | Importing the package loads every stage and its heavy dependencies (pandas, geopandas, scikit-learn) | `__init__.py` | The first import takes seconds; the adapter imports it lazily |
| 10 | Option ids come from a counter shared by the routing threads and `od_results` are appended in completion order; a resumed build reloads `od_cache.json` and restarts the counter at 0, so new ids repeat cached ones. Step 4 draws each pair's demand in file order from one seeded generator | `routing/route_builder.py:121, 149, 253-255, 328-332`, `instance/generator.py:110-116` | Never resume: every routes step starts in an empty directory. After step 3 the adapter sorts `od_results` by (`from_id`, `to_id`), or the same seed gives different travellers on each build. Option ids are labels valid inside one build only |
| 11 | Itineraries without public transport (bike alone, walk alone) are classified and dropped | `routing/route_builder.py:120-139, 209-215` | Shared bike alone is not in the model: three modes, public transport with bike, public transport alone, car |
| 12 | A failed public-transport query, or one with no usable itinerary, drops its pair silently; a failed car query keeps the pair without a car option | `routing/route_builder.py:188-207, 222-230` | After the retries the worker records each failed query from its log template as a `route_failures` row and counts `queries`, `queries_failed` and `failure_pct`; the pairs without a route are not in the instance |
| 13 | The solver reports its errors with `print` and returns `None`; `optimizer.solve` then writes `null` to `optimization_instance_results.json` | `optimizer/solver.py:626-638, 875-890`, `optimizer/__init__.py:71-75` | The outcome of a solve is read from its return value and its captured output, not from an exception |
| 14 | The PT+Bike rows of the solution exist only for offered options (`nu > 0.5`); PT-only and car rows exist for every option | `optimizer/solver.py:694-711, 738-778, 337-347` | An option with no row has no flow and no price, and is not available in the simulation with the model's prices |
| 15 | The number of bike legs `k`, which multiplies price and cost in the objective, is not in the solution; the package's parser computes it | `optimizer/solver.py:579-581`, `optimizer/parser.py:54-78` | Step 4's child calls `parse_json_instance` on the instance and writes `option_bike_legs.json`; the ingestion stores `bike_legs` per option |
| 16 | Clustering runs in EPSG:3857, so the grouping distance and the hub outline margin are Web-Mercator units, shorter than ground metres by cos(latitude): at Geneva (46.2°) the default 500 groups stations within about 346 m; the minimum trip distance is a haversine distance in metres | `clustering/strategy.py:12-13`, `routing/od_permutations.py:30-35` | The two distances are not in the same unit; to report with the rule "minimum trip distance greater than grouping distance" |
| 17 | `stops.txt` holds parent stations and their platforms at the same coordinates (`location_type` 1 and 0), and `load_gtfs_pt_stations` keeps both | `stations/gtfs.py:16-28` | The stop count is the package's count (66 inside 500 m of the Geneva centre) |
| 18 | The choice-model coefficients are local constants of the solver, repeated as defaults of `compute_p_off` | `optimizer/solver.py:87-101`, `optimizer/p_off.py:5-9` | They appear in no output; read from the solver's source |
| 19 | The package summary counts PT+Bike flow only where `Flow (q) ≥ 1` | `optimizer/metrics.py:58-59` | The Lab's modal split sums every flow and adds up to the demand; the difference is visible in the Advanced view |
| 20 | The trip-planner client fixes its retry policy in `__post_init__` (2 retries, 0.1 s backoff, connection errors only for `POST`) with no parameter | `routing/otp_client.py:63-71` | The stage child mounts the demonstrator's policy on the client's session at run time (story 2-8); the package's files are not touched |
| 21 | `optimizer.solve` always computes its own upper price bound, 0.2 above the lowest price | `optimizer/__init__.py:39-46`, `optimizer/p_off.py:72-73` | No value of its parameters fixes the price; a flat price needs the inner solver function the package exports |
| 22 | `PipelineConfig.seed` defaults to `None` | `config.py` | An instance version's seed column is not null: the demonstrator stores 42 when it starts from the package defaults (not a model change) |
| 23 | `generate_instance` names its file `Instance_{number of pairs}.json` | `instance/generator.py:192` | The stage child renames it `Instance_1.json` (a file name, not its content) |
| 24 | **Found by a characterisation run (2026-11-27):** with pandas 3 a stop's `lines` is not a numpy array when the route names are text, so `build_hubs` raises "The truth value of an array with more than one element is ambiguous" on the Geneva feed | `clustering/hub_builder.py:33`, `stations/gtfs.py:36-43` | The stage child sets pandas' `future.infer_string` to false before it runs the package (`stage_runner.keep_object_strings`); to report to the author |
| 25 | **Found by a characterisation run:** the package writes `hub_polygons.geojson` with the property `cluster` (not `hub_id`), `stations_hubs.geojson` with `identifier` and `station_type`, and the instance's arcs as one list per pair keyed `{from}_{to}` | `clustering/strategy.py:34-60`, `instance/generator.py:150-167` | The domain readers and the fake city read and write those shapes |

Entries 1, 2, 5, 8, 10 to 14, 16, 18 to 22 were read in the code and not yet reproduced by a run on
this set-up (10 and 18 were re-checked on 2026-11-25). Entries 4, 9, 15, 17 and 23 to 25 were
